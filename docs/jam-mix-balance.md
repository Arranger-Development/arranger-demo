# 四轨合奏音量平衡

本轮针对整个合奏校准，保留原始采样、音符、力度、起音、时值和自然尾音。

| 轨道 | 深秋源增益 | 压缩阈值 / 比例 | 输出校准 | 目的 |
| --- | --- | --- | --- | --- |
| 鼓 | −7 dB | −14 dB / 2.5:1 | −3 dB | 保留起音，收敛密集鼓点 |
| 和弦 | +4 dB | −14 dB / 1.6:1 | 0 dB | 保持分解和弦可辨，缓和密集叠音 |
| 贝斯 | 0 dB | −18 dB / 4:1 | −8 dB | 控制自然采样重叠形成的持续能量 |
| 旋律 | +2 dB | −18 dB / 2:1 | −1 dB | 保持主线清楚，缓和突出的音符 |

输出校准基于真实浏览器的整条动态通道测量，包含原生压缩器的增益行为。四轨是各自独立的动态通道，不跨轨自动挪动推子；静音、复制轨道和效果器重接互不串扰。实时音源与Jam效果输出复用同一通道；整段和分块WAV使用相同参数。

“平衡四轨”恢复当前项目推子到0 dB校准起点，静音和其他效果不变。已在用户当前Chrome项目应用该配比，将之前偏高的鼓推子从+6 dB恢复到0 dB并持久化。

## 验证材料

- `scripts/jam_mix_balance_fixtures.mjs` 使用生产模板、播放适配器、事件力度和精确时值，生成四轨测量乐句，覆盖稀疏、密集、深秋和旋钮模板。
- `scripts/analyze_jam_mix.py` 用本地ffmpeg和numpy辅助检查原采样与干声（线性插值近似Web Audio）。最终动态结果以浏览器实际渲染为准，不用其他压缩器模拟代替。
- 打开 `/arranger-demo/output/jam-mix-balance/verify.html`，点击“渲染验证”。通过生产 `renderProjectToWav` 分别渲染四个stem和混音；调整前使用原源增益且关闭新增动态，调整后使用最终完整通道。验证不读取或修改用户项目。
- `output/jam-mix-balance/browser-metrics.json` 保存实际浏览器PCM结果。常用乐句四轨平均RMS差由8.2 dB降至2.3 dB，密集合奏由15.1 dB降至3.1 dB，中档旋钮乐句由15.6 dB降至6.9 dB；所有检查的混音削波样本数均为0，包括鼓推子+6 dB的压力场景。乐句密度和原有力度差仍保留。
- `before-matched.mp3` / `after-matched.mp3` 为浏览器实际渲染的同一组四轨乐句、前12秒。调整前降低1 dB，两段整体响度约−16.2 LUFS，便于比较配比而非整体音量。

903项测试、lint与build通过；构建保留已有大包提示。新增测试覆盖进入Jam时复用通道、推子和静音、复制轨道独立及释放、整段与分块WAV的相同轨道处理。真实PCM测量覆盖自然尾音、叠音、分解和弦与源力度；本轮未进行主观听音验收，对比音频供用户判断最终听感。
