# Jam 编辑器实时播放

2026-11-02，按用户确认取消编辑器试听按钮，四轨共用自动循环。后续即时编辑版本已移除底部播放及所有手动保存入口，当前自动保留规则见 [即时编辑与自动保留](jam-live-retention.md)，音乐模板、采样映射、音量平衡和项目存储格式不变。

## 交互

- 播放或等待启动时新建、打开任意已有乐句都采用合奏内编辑：原乐句、等待、起点和尾音持续。新乐句写入首音，或尚未播放的已有乐句首次修改音符/旋钮后，目标轨在下一小节从头加入，同轨已有乐句到边界才替换。正在播放的乐句打开时不改进度。
- 合奏内手工编辑/撤销保留起点；整条音型切换只在下一小节重启目标轨。等待前删空取消新请求并保留原乐句，进入后删空只停止该轨。退出编辑不停止或重新调度合奏。
- 停止时重新进入编辑器沿用独奏覆盖层和整条自动循环，退出后停止；手动暂停的当前编辑会话仍优先保持暂停。
- 空格和硬件总播放键在合奏内编辑时控制整个组合，在独奏时控制编辑循环。显式暂停或取消等待优先于自动加入，后续修改不会擅自抢回播放。输入框、滑块及其他按钮保留原有键盘语义。
- 小节翻页只改变查看位置；工具栏另外显示实际发声的小节，游标由音频的 `onAudible` 确认。编辑页不会因为调度提前量而提前显示新模板的播放位置。
- 每次编辑自动更新当前宝石及浏览器存储，不再区分待保存草稿与模板。更新保持乐句ID和槽位，不额外重启循环；名称更新不截断声音。

## 播放实现

`jamAudition.js` 管理编辑所有权、暂停意图、是否空白、原合奏恢复资格及编辑版本。`sessionPlayback.audition` 支持明确的 `restart`；从停止进入编辑也使用独奏覆盖层，不把草稿当作底层合奏。原先界面上任何轨道存在等待请求就阻挡草稿更新的条件已移除。

`jamTrackPlayback.js` 对手工更新保留覆盖层的起点，对整条模板更新重设起点。底层等待请求在独奏期间仍按时钟推进，但不会截断编辑声音；恢复后才按实际发声确认并清除等待。覆盖层版本阻止旧回调覆盖新的编辑或恢复已暂停的状态。编辑版本仅存在于运行态，不写入项目或乐句数据。

准备音色期间退出或暂停会使旧启动请求失效。音频加载失败保留错误及草稿，并将编辑停在暂停状态；继续编辑不会自动重试启动，用户可明确播放重试。
