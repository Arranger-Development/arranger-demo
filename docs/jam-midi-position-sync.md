# Jam MIDI 推子初始值与旋钮直接接管

## 当前规则

2026-11-02，用户根据实机结果确认：四颗推子记录并同步其上报的初始值；两颗旋钮不再要求静止初始化，任何有数值变化的转动直接接管，无需经过指定位置或执行复位。旋钮没有上报前显示原有乐句参数，不再显示“待同步”。不需要用户联系厂商或修改固件才能使用本轮功能。

推子原始值与映射后效果值单独保存在本次连接的状态中。音量、滤波和混响收到消息后同步当前效果目标，包括多选目标；弯音停止时先记录并显示，播放就绪后应用，停止/失焦释放声音，断线清除本次记录。端口打开期间先暂存，打开成功后提交，打开失败或取消不会应用这批初始效果。页面未激活或失焦时暂存的推子值在有效上下文恢复后同步；旋钮消息只更新位置，不延迟提交音符修改。切换效果目标不自动覆盖新目标，之后收到推子消息就直接更新。

## 设备与已验证的限制

用户此前提供的型号资料为 [NULL39 MIDIF4C4 厂商说明](https://null39.work/asset/midi%E8%AF%B4%E6%98%8E/Device/MIDIf4c4EN.html)。项目识别 `4AC1F4C4`、`4AC0F4C4` 和 `MIDIF4C4`，沿用已实测的通道4、CC5左旋钮、CC6右旋钮。和弦左侧为色彩、贝斯/旋律左侧为旋律，均对应Level；三轨右侧为律动，对应Int。鼓仍为左强度、右律动。物理位置缓存仍沿用旧键名，音乐命令按当前轨道转换；CC1–4效果推子绑定保持原样。

2026-11-02，通过 macOS CoreMIDI 在当前电脑识别到 `4AC1F4C4`，只读打开输入并保持旋钮不动监听5秒，收到0条消息。这只验证了打开软件输入连接的行为，不能据此断言所有固件都不支持开机上报。公开说明未列出当前位置查询、全量位置快照或开机发送设置；厂商配置工具静态检查也未找到可确认的位置读取入口，未执行配置工具或修改设备设置。手册的内部记忆功能指MIDI绑定配置，不等于向网页上报旋钮物理位置。

网页只有收到设备真实数据后才能知道位置，不使用localStorage旧值冒充当前位置。用户已经取消旋钮静止初始化的要求；以下保留原始实机观察作为选择当前交互规则的依据。

## 已实现的行为

- 独立外部状态保存两颗旋钮的原始CC值与百分比。`round(raw / 127 * 100)`用于指针、数字与无障碍描述，例如38显示30%；模板生成继续使用现有五档／六档规则与边界防抖。
- 未打开编辑器、界面失焦或确认框打开时仍接收位置，但不提交音乐命令。之后打开编辑器只显示位置，不回放先前消息、不替换手工音符或新增撤销记录。
- 在打开端口前安装监听器，打开期间收到的旋钮消息仅同步位置，不改变音乐参数；推子消息暂存至打开成功再同步效果。没有已知的快照协议时，不用时间窗口或“吞掉第一条消息”猜测快照：端口就绪后的首次真实转动立即处理。
- 两颗旋钮取消经过软件当前值后接管；切轨后新位置变化直接作用于当前编辑轨。相同原始值的重复消息不重生成模板，也不覆盖撤销结果。
- 本次连接中收到的物理位置在切轨时继续显示。鼠标、键盘、模板下拉、其他控制器命令及撤销／重做显示软件参数；物理位置单独保留，下一次实际转动重新显示物理百分比。无障碍描述区分物理位置与当前乐句参数。
- MIDI连续手势沿用300ms合并撤销。断线、重新连接和卸载清除物理位置；普通失焦与编辑器切换不清除。四颗推子与两颗旋钮均不再使用经过当前值后接管，Launchpad绑定不变。

## 验证

自动化覆盖无初始消息、端口打开期间的位置消息、首个实际转动、重复上报、无编辑器/失焦/确认框时的位置捕获、五档/六档映射、鼠标与撤销的显示归属、切轨保留位置、断线清理、取消连接及Launchpad监听隔离。

浏览器使用独立内存项目与模拟MIDI输入检查：未打开编辑器时接收38，再创建空白贝斯，指针显示30%、乐句参数保持50且撤销不可用；连续输入39、83、105后显示83%、模板参数75，一次撤销恢复原始50和空白内容。模拟结果不能作为硬件支持静止位置上报的证据。

页面还通过和弦六档、切轨不重生成、手工音符被模板替换后整次撤销恢复、键盘修改与撤销、模拟断线重连的检查。1440×900、1280×720、1024×600和720×900均检查编辑器可达性并保存截图到 `output/playwright/jam-knob-sync/`；编辑器本身均无纵向溢出。

最新规则额外验证：重放实机的CC1–4初始批次，成功连接后应用，失败连接不应用；停止时记录非零弯音6.8并显示，播放就绪后应用、停止后释放；失焦暂存推子值、恢复后同步；多效果目标的锚点参数恰好相等时仍更新所有目标。独立页面实测初始音量6dB/滤波关闭/混响0/弯音6.8，随后直接调整为音量0dB/滤波10000Hz/混响50%；旋钮原始值38立即显示30%并选择25档，律动原始值0直接进入0档，均无需经过软件值。`npm test`共965项通过，`npm run lint`与`npm run build`通过，构建仍有原有的大体积包提示。

## 实机观察记录（用户已取消旋钮静止初始化要求）

静止USB拔插上报仍未完成验收。第一次150秒监测只观察了端口列表，没有收到消息；CoreMIDI可在USB重新接入后保留相同端口引用，不能用端口列表未变化断言没有发生拔插。

随后在持续被动监听期间，用户确认完成USB拔插。记录到CC5数值46→45→44，以及一组CC1–4数值127/0/0/65，未观察到CC6。用户对期间是否碰动强度旋钮的最终回复为“不好说”，因此这批CC5消息的触发原因不确定，不能作为旋钮静止自动上报的证据，也不能据此宣称所有旋钮不支持上报。记录保存于 `output/playwright/jam-knob-sync/hardware-observation.json`；监听没有向硬件发送任何消息或修改设备配置。

用户随后确认“又试了两次”。监听在第206.147秒与244.812秒分别记录到两组CC1–4（127/0/1/65和127/0/0/65），两次均未收到CC5或CC6。这两次重复结果确认：当前这台设备及设置在USB重新连接时没有向已连接的输入监听器提供两颗编辑旋钮的位置；不能用推子的上报代替旋钮上报。现有网页代码无法据缺失消息恢复旋钮的真实位置，静止初始化仍需厂商提供主动上报设置、已确认的位置查询协议或相应固件支持。此结论不等于断言所有固件、所有协议均不支持位置读取。测试结束后已关闭临时只读监听。
