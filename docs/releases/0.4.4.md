# v0.4.4 · Jam 交互与音频修复

对应 Notion「功能和设计需求」13.1–13.10。十项已完成；需求正文仍只保留「需求描述」「预期效果」，完成状态通过数据库属性记录。

- 移除顶部操作提示，保留导航和键盘控制。
- 屏幕空素材格显示低亮边框，悬停也不出现加号；Launchpad 空格改为各轨低亮色，已有素材及播放/排队状态保持区分。
- 鼠标、键盘、MIDI 旋钮更新走同一入口，在下一个可调度步生效，保持轨道播放起点及编辑小节。显式音型选择仍可重新播放。
- 删除仅移除目标 ID，后续素材位置、其他轨道、草稿位置及有效旧工程空位不再压紧。

- 当前素材卡片接入外围进度条，使用实际可听乐句及各轨循环进度。

## 音频

- 深秋鼓组校准 −5.5 dB、和弦 +2.5 dB、旋律 +0.5 dB，贝斯 0 dB；用户推子、静音和工程数据不改写。
- 自然模式的和弦不再被 authored gateDuration 截断；乐谱/MIDI 时值保持原样，门控和弦及贝斯仍遵守时值。
- 手动停止使用即时音频时钟，使旧调度失效，停止声部并清除重复器、刹停及混响缓存。独立输出门控在 5 ms 内淡出，在下一次播放的首个调度音符处恢复；用户推子不参与门控。

## Launchpad 行顺序与编辑器跟随

当前 Jam 主网格从上到下为：白色整列播放（Note 81–88）、鼓（71–78）、和弦（61–68）、贝斯（51–58）、旋律（41–48）。对应右侧效果目标按钮依次为 CC79、69、59、49；顶行右侧 CC89 不分配功能并保持熄灭。底部效果垫及旧版映射不变，输入和灯光共用当前行定义。

编辑器展开时，Launchpad、鼠标及电脑快捷键触发乐句会立即切换编辑对象；跟随只绑定编辑内容，不增加试听、重播或启动请求。原有播放/暂停/取消排队行为保留，修改内容及各乐句撤销记录保留。收起后触发已有乐句保持收起；编辑按钮和空格创建仍可显式打开编辑器。效果目标选择与编辑对象独立。

追加验收：1051 项测试、lint、build 全部通过。浏览器通过模拟 Web MIDI 端口走完整输入与 LED 链路，并验证鼠标、快捷键、同轨/跨轨跟随、取消排队、收起后行为、名称和撤销记录保留；模拟跟随切换未增加播放启动次数。实体 Launchpad 尚未实测。

浏览器验收使用独立窗口及原生视口（未设置固定视口模拟），结束后关闭独立验收窗口。截图及结果：`output/playwright/jam-follow-editor.png`、`output/playwright/jam-follow-metrics.json`。

## 空工程首次创作连续播放

Jam 常规编辑从第一条乐句起统一进入分轨合奏，不再依赖是否按过整列播放。空乐句保持安静；首条乐句生成内容后自动进入正常单轨循环并记录播放选择。创建下一轨的空乐句只切换编辑对象，已有声音、播放起点和循环进度保持不变。新轨出现内容后在下一小节加入，同轨新乐句有内容后才按边界替换原乐句；普通音符及旋钮修改继续保持播放位置。内部显式独奏能力保留。

新增 9 项首次创作回归测试，覆盖旋钮、音型选择、手动添加首音符，四轨连续叠加、同轨替换、删除音符、暂停后编辑、首次采样加载中切轨及加载失败。最新完整结果：`npm test` 1060/1060 通过，`npm run lint` 与 `npm run build` 通过，`git diff --check` 通过。

独立原生尺寸浏览器从真正空项目开始，未预置乐句、未点击整列播放，通过鼠标和模拟 Launchpad 依次创建四轨。实际音频 PCM 均非零，四轨播放起点分别为 0、32、48、64 步，后加入轨道均在小节边界进入，整个叠加过程仅一次播放启动。新建空和弦时鼓声保持，收起编辑器后合奏保持，同轨替换未重置其他轨道，暂停后修改及创建下一轨保持静音。另在两个独立空项目验证和弦音型选择及旋律手动加音符的首次启动。控制台无错误；验收窗口已关闭，未连接实体 Launchpad。

截图及测量记录：`output/playwright/jam-first-four-tracks.png`、`output/playwright/jam-first-metrics.json`；验收脚本：`output/playwright/jam-first-qa.js`。

## 已知问题

用户反馈：通过 Launchpad 切换乐句后，编辑器显示已切换，但使用实体旋钮控制器调整时，实际编辑可能仍关联上一个乐句。该问题尚未定位和修复，现有模拟输入及浏览器验收不能视作实体旋钮绑定通过。本次按确认范围发布当前版本，后续单独修复并验证实体旋钮切换后的编辑目标。
