# 0.4.0 Jam / Live

## Behavior

- The AI recommendation screen branches directly to Live or creation. Creation’s performance entry also opens Live; there is no Jam/Live mode switch. Both use the chosen BPM, track enablement and requested timbre IDs. AI analysis remains the existing local demonstration.
- Live’s section library has a fixed “编辑／保存段落” entry that opens the existing Jam editor in a large modal. It opens the selected section or resumes the last draft. Saving updates the library immediately and keeps the editor open. “完成编辑” or Escape closes it; clicking the backdrop does not. Live columns, scroll position and selected track remain in place, and focus returns to the entry. Unsaved drafts remain in memory without a confirmation prompt.
- Jam has ten main phrase slots and four transition slots per track. Visible slots keep the supplied catalog order (first ten main phrases and four transition slots); each dropdown contains ten unavailable placeholder choices. Existing pad bindings remain in storage for compatibility but no longer replace the supplied visible templates. Saved sections keep independent phrase selections and timbre choices. Save is explicit; there is no unsaved-change prompt. The bottom Add control creates an empty main section or transition, with separate numbering and no five-section limit.
- Clicking a section starts playback; clicking it again stops. New targets queue for the next schedulable bar boundary. A second click on the pending target cancels it. A transition replaces all tracks once (empty tracks are silent), then restarts the preceding main section from bar one.
- Clicking a saved Live library section selects and previews its saved snapshot. Main sections loop; a second click stops; transitions finish once without returning. Other targets queue at the next bar and a duplicate pending click cancels. Preview immediately takes over from the arrangement and never resumes it automatically. Cards display preparation, pending, audible status and audio-clock progress. Placement remains available during preview and stops it on success; dragging does not trigger a click preview. Starting the arrangement takes ownership back.
- Live copies resolved notes, phrase lengths, names and requested timbres. Editing/deleting Jam originals or replacing a slot does not rewrite Live. Empty columns are skipped; finite songs stop; infinity exits on an immediate manual column launch. Clicking any music cell selects its effect track and immediately starts that column from beat one, then continues the arrangement. Empty columns locate the next playable column; an empty suffix shows a message. Structure editing is disabled during playback. Both pointer dragging and button-based placement/reordering are supported. Column headers and music cells drag the complete column, with insertion feedback and edge scrolling; release never launches playback.
- Live transport provides rewind, stop and play/pause. Pause/stop retain the audible column ID, repeat cycle and sixteenth-note position; play resumes there, while finite completion resets the next play to the beginning. Preview preserves this separate cursor. Space toggles play/pause and Escape stops outside editable controls and dialogs.
- Live has 50-step undo and redo for structure, BPM and static mix only. Text edits and slider/drag gestures are grouped into one checkpoint; unchanged edits add none. Restoring history stops playback, restores its cursor and updates local storage without changing saved sections or drafts. Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z mirror the toolbar. History itself is session-only.
- Live export expands repeats into a creation project, asks for finite counts for infinity, and preserves BPM, static mix and timbre metadata. The creation replacement is one undo checkpoint. The limit is 256 bars; over-limit exports cannot mutate creation.
- Live selects an effect target by clicking a track header or grid cell. The right-side panel controls only that track and retains each track’s settings while switching; the repeater releases on target changes.
- Every track has a low-pass control and an audio-slice repeater (quarter/eighth/sixteenth note). The transport continues during repetition. Release, pointer cancellation, blur, stopping and changing views reset repeat buffers. Filter/repeater are not exported.

## Content handoff

`src/data/aiPerformanceTemplates.js` is the current AI phrase catalog, consumed through `performanceTemplates`. Existing entries remain main phrases. Add `kind: 'transition'` to supplied transition entries; keep stable unique IDs, `name`, `barCount`, and the existing `bars` score format. No transition music or filler phrases are generated to fill empty slots.

`src/app/performanceSession.js` defines `TIMBRE_OPTIONS`. The chosen placeholder ID is stored in each section and as `requestedTimbreId` on exported cells/clips. The actual existing `timbreId` remains the audible fallback; do not overwrite the requested ID when binding new sample banks later. No new sound assets are included in this release.

## Storage and audio boundaries

Version 4 sessions use `arranger-performance:v4:<profile-or-genre>`. The reader migrates legacy five-slot sessions without deleting their original keys. Only saved sections, pad bindings, Live columns and static mix are persisted; performance cursors and held effects are transient.

`createSessionEditor` owns synchronous draft/save state. `createSessionPlayback` owns Jam/Live transitions. `AudioEngine.playbackSource(absoluteStep, audioTime)` resolves the local step offset before fetching the boundary's events, while `onAudible` updates the UI through Tone Draw. The workspace view is `live` or `creation`; legacy `initialView: 'jam'` maps to Live. The section editor shares the existing session and drafts without a storage migration. Opening or closing it stops playback, releases repeaters and disables filters while preserving track volumes. Jam keyboard and Launchpad commands are bound only while the modal is open. Creation, the section editor and Live stop the previous owner before starting another.

Long WAVs are rendered in 30-second output chunks. Each chunk has preroll covering the longest actual voice, then trims to exact absolute sample boundaries and emits a PCM Blob part. Existing short-file rendering is preserved up to 120 seconds including tails. The float buffer size depends on a chunk plus voice tails rather than the complete song. Final PCM storage still necessarily grows with song duration.

## Validation

### 创作模式主动扩充小节（10.26）

时间线末尾“＋”每次追加一个空小节；顶部“小节数”显示实际工程长度，点击后填写目标总数并按“扩充”或 Enter 确认。Esc／取消不修改，失焦不提交。只允许增加，最多 256 小节，达到上限禁用两个入口。

扩充会给所有现有轨道补齐空格，不自动创建 clip；新增位置可照常添加、移动或粘贴片段。每次扩充是一次撤销操作，原有内容、选择和混音保留。播放中扩充会停止声音但保留定位，不自动续播；录音／倒数及教程锁定时不能扩充。短工程显示的至少八个编辑位置不等于实际长度，四小节工程点击“＋”仍只扩到五小节。

空白尾部计入播放、项目 JSON、MIDI 和 WAV 的长度，不改变文件格式。应用目前没有工程文件读取入口，本轮验证 JSON 长度与矩阵序列化及撤销恢复，不新增“打开工程”功能。

自动化验证覆盖 8→9／32、255→256／拒绝 257、非法值无修改、短工程、额外轨道、单步撤销重做、新增区域 clip 操作及 MIDI／WAV 空白尾部长度。浏览器已验证两个入口、错误提示、Enter／Esc、焦点返回、播放中扩充保留定位、256 上限及标尺／网格对齐。设备听感及持续密集编辑性能测量仍待专项验收；此前 review 的发布产物检查、Live 撤销边界及导出弹窗问题不属于本次修正。
