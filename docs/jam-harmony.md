# Jam 自动和声：从一段旋律到可编辑的伴奏

这套规则用于哼唱预览的录音和手写旋律。录音识别只负责提供音高、起音和时值，手写旋律直接提供相同的数据。和声在浏览器里计算，相同输入会生成相同结果。

## 1. 读出旋律和重音

- 从现有 Jam 乐句读取每个音的实际起音、时值和音高。一个长音跨越两个半小节时，两段持续时间分别参与打分，旋律本身仍只起音一次。
- 每半小节最多选一个基础和弦。音符的权重是它在这个窗口内的时值乘以节拍权重：小节头 1.65、第三拍 1.35、其他拍头 1.15。短而轻的弱拍音再乘 0.4。
- 如果一个音夹在两个紧邻的音之间，前后都只移动一两个半音，而且本身不超过一拍，就视为可能的经过音或邻音。它在和弦打分中只占四分之一。调性分析保留更多权重，避免误丢掉音阶的信息。

## 2. 先估整句的调，再选和弦

每个大调和小调都有一个分数。分数来自旋律音在音阶里的稳定程度、持续时间、起止音，以及主三和弦的三个音是否都在旋律里出现。首尾落在主音更有利。小调里上行半音回到主音的升七级单独处理。

只在与最高分足够接近的调里找方案（差值不超过 2.5 或最高分的 10%，取较大值）。一两个局部音与另一个调刚好相配，通常不足以换掉整句的调。已有手写贝斯时放宽候选调，优先满足它给出的约束。

| 调式 | 常用候选 |
| --- | --- |
| 大调 | I、ii、IV、V、vi |
| 小调 | i、III、iv、v、VI、VII；旋律支持时可用大三和弦 V |

对每个窗口和候选和弦：

- 和弦内音加 `0.75 × 权重`；和弦外音扣 `0.22 × 权重`。如果有和弦音与它相差半音（不计八度），扣分变成 `0.68 × 权重`。
- 主和弦有起句和收句优势，前提是它包含该处旋律的首音或尾音。和弦包含旋律全句从未给出依据的音会小幅扣分。
- 换和弦需要付出代价：小节头低一些、第三拍高一些。V 到 I 或 i 的代价较低。整句最后还会检查回到循环开头的衔接。
- 半小节完全没有旋律、也没有手写贝斯提示时，和弦和自动贝斯让出空间。

用动态规划求整条循环的最高分路径：

```text
路径分数 = 调性证据 + 各段旋律与和弦的匹配
        + 起句与收句加分 - 换和弦与循环衔接的代价
```

例如，四小节的 `E D C D | E E E 休 | D D D 休 | E G G 休`，会配 `C | C | G | C`。在 C 大调上行音阶中，短暂的 F、B 不会分别把和弦拉走，最后的 C 可以落在 C 和弦上。

## 3. 把和弦排成实际能响的音

同一个三和弦可以换八度、转位、拉开声部。算法在 G2–C5 内试这些排法：

- 优先避开和旋律同音区的半音与全音摩擦。比较的是音色**实际发出的音高**。例如深秋旋律的采样实际比存储键位低一组。
- 给旋律留空间，避免在低音区挤着排三度。起句和收句倾向于把根音放在和弦的最下面；必要时仍可以转位。
- 相邻和弦尽量让每个声部少跳，循环接缝也算。同一和弦持续时，保持同一套音高排列。重复的第三拍落点会更轻。

## 4. 贝斯、鼓和手动编辑

- 自动贝斯从和弦的根音生成，在半小节起点落音，少量附加落点可跟底鼓。切分不改变和弦根音。鼓保留底鼓和军鼓的骨架，再按旋律起音密度调整踩镲。
- 如果同列已有手写和弦，补贝斯时读它**实际播放的音**。有明确根音就用该根音；普通转位三和弦从组成音找根音。遇到不完整或不明确的排列，用最低音作为低音依据。同一半小节内的手写换和弦位置会保留。
- 如果同列已有手写贝斯，新和弦每半小节必须包含最强的贝斯音，允许它是根音、三音或五音。若调内没有合适的三和弦，则允许在该处使用贝斯音作根音的局部三和弦。两条轨长度不同时，在可存储范围内配一个完整公共循环，超过时优先跟住固定贝斯的循环。
- 生成结果落入普通 Jam 乐句和 `notePerformances`。旋钮只调整演奏方式。点「重配和声」时，已手写或改过的乐句作为约束，未手改的生成和弦与贝斯可更新。

当前目标是稳定的流行大调和小调伴奏。旋律可能有多种成立的和声，短句也未必足够确定调性。此版本用基础三和弦做默认结果；不会主动加入七和弦、替代和弦或在一句里转调。核心代码见 `src/preview/humHarmony.js`，配轨渲染见 `src/preview/humArrangement.js`。
